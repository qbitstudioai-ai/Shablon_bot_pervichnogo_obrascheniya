# Правила именования

Цель: названия должны быть понятны куратору и одновременно не создавать технических проблем.

## 1. Supabase

Физические имена schema, таблиц, столбцов, индексов и функций пишутся:

- латинскими буквами;
- русскими словами в понятной транслитерации;
- в нижнем регистре;
- через знак подчёркивания;
- без пробелов, кавычек и специальных символов.

Примеры:

- **kompaniya_001**
- **dokumenty_znaniy**
- **identifikator_dokumenta**
- **data_sozdaniya**
- **aktiven**

Кириллица в PostgreSQL технически возможна, но часто требует кавычек, усложняет SQL и интеграции. Поэтому она не используется в физических именах.

Для каждой таблицы и важного столбца добавляется русское описание через **COMMENT ON TABLE** и **COMMENT ON COLUMN**. Понятное объяснение также хранится в [DATA_DICTIONARY.md](DATA_DICTIONARY.md).

## 2. n8n

Названия workflow и нод пишутся по-русски, чтобы схема читалась как инструкция.

Примеры workflow:

- **Компания — Бот первичного обращения**
- **Компания — Служебный бот и база знаний**

Примеры нод:

- **Телеграм — Получен документ**
- **Проверить отправителя**
- **Рассчитать SHA-256**
- **Опубликовать новую версию**
- **Отправить отчёт**

Технические переменные и ключи JSON пишутся латиницей в snake_case.

## 3. Credentials

Credential получает название, в котором видны компания, сервис и назначение:

- **KOMPANIYA01_TELEGRAM_KLIENT**
- **KOMPANIYA01_TELEGRAM_SLUZHEBNYI**
- **KOMPANIYA01_SUPABASE**
- **KOMPANIYA01_OPENAI**

Сами секреты никогда не сохраняются в GitHub и документации.

## 4. Markdown-документы

Имя файла понятно человеку, но не является главным идентификатором документа. Постоянный идентификатор хранится в поле **identifikator_dokumenta** внутри файла.

Рекомендуемое имя файла:

**okna-plastikovye.md**

Постоянный идентификатор:

**okna_plastikovye**

## Почему выбран такой подход

PostgreSQL допускает нелатинские буквы, но некавыченные имена приводит к нижнему регистру, а кавычки делают имена чувствительными к регистру. Поэтому простые ASCII-имена надёжнее для SQL, n8n и будущего кода.

Источник: [официальная документация PostgreSQL об идентификаторах](https://www.postgresql.org/docs/current/sql-syntax-lexical.html).
