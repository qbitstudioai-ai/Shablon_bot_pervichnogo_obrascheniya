# Имена и значения

## Supabase и внутренние данные

Собственные имена schema, таблиц, столбцов, функций и ключей обмена: понятная русская транслитерация, нижний регистр, snake_case, ASCII, без пробелов и кавычек. Максимум для SQL-имени — 63 байта. Примеры: **kompaniya_001**, **soobshcheniya**, **data_otpravki**, **tekst_fragmenta**, **vektor**.

Кириллица в PostgreSQL допустима и не обязательно требует кавычек. Транслитерация выбрана для удобства интеграций и единообразия, а не из-за запрета русского языка. К таблицам и полям будущая миграция добавит русские COMMENT. [Правила PostgreSQL](https://www.postgresql.org/docs/current/sql-syntax-lexical.html).

Исключения: общепринятый **id**, имена системных объектов PostgreSQL/Supabase и поля внешних API не переименовываются. Например, Telegram chat_id и embedding провайдера преобразуются адаптером во внутренние имена. Названия встроенных функций и типов pgvector остаются исходными.

В примерах используются только вымышленные компании. Схема **kompaniya_001_test** — тестовая; **kompaniya_001** — рабочая. Их права и Credentials различаются.

Для нескольких проектов одной компании имя schema включает понятный код проекта. Для первой установки qBit canonical schema — **qbit_bot_pervichnogo_obrascheniya** вместо прежнего **qbit_test**. Имя schema задаётся только доверенной конфигурацией и не формируется из текста клиента или ответа модели. Роли **qbit_test_*** в текущей задаче сохраняются без переименования.

## Статусы

Точные списки кодов принадлежат [жизненному циклу](specs/CONVERSATION_LIFECYCLE.md), [надёжности](specs/RELIABILITY_AND_MEMORY.md) и [загрузке знаний](specs/KNOWLEDGE_INGESTION.md). Интерфейс показывает русские подписи.

Коды старых документов active, waiting_user, converted, declined, lost_no_response, phone_received, order_intent, measurement_booked больше не являются нормативными. Реализации ещё нет; миграция рабочих данных не требуется. Не смешивать старые примеры с текущими списками.

## n8n и Credentials

Workflow и ноды называются по-русски, например «Проверить отправителя», «Сохранить входящее событие», «Опубликовать версию». Переименование ноды не должно ломать обработку: необходимый контекст передаётся в данных; не строить логику на хрупких ссылках по имени ноды.

Credentials обозначают компанию, среду, компонент:

- KOMPANIYA01_PROD_TELEGRAM_KLIENT;
- KOMPANIYA01_PROD_TELEGRAM_SLUZHEBNYI;
- KOMPANIYA01_TEST_TELEGRAM_SLUZHEBNYI;
- KOMPANIYA01_PROD_POSTGRES_BOT;
- KOMPANIYA01_PROD_POSTGRES_ZNANIYA;
- KOMPANIYA01_PROD_LLM.

Название Credential само по себе не ограничивает доступ. Разрешения заданы в [ACCESS_AND_ISOLATION.md](specs/ACCESS_AND_ISOLATION.md).

## Документы, задачи и версии

Markdown-файл может менять имя. Постоянным ключом остаётся identifikator_dokumenta внутри YAML, например **okna_plastikovye**. Внутренние номера версий назначает система.

Задачи имеют постоянные ID: DOC-01, PRE-01, DB-01, KB-01 и далее. Один ID не используется повторно для другой задачи. Версия документационной основы **0.2** не означает готовый программный релиз.
