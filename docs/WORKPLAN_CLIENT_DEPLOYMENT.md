# План внедрения шаблона для новой компании

Этот план используется после завершения основного шаблона.

## 1. Сбор данных

- [ ] Название, логотип и контакты компании.
- [ ] Каналы обращений.
- [ ] Этапы продаж и целевые действия.
- [ ] Правила передачи человеку.
- [ ] Часовой пояс и рабочее время.
- [ ] Разрешённые сотрудники для служебного бота.
- [ ] Документы базы знаний и контрольные вопросы.

## 2. Отдельные ресурсы компании

- [ ] Создать клиентского Telegram-бота, если он используется.
- [ ] Создать служебного Telegram-бота.
- [ ] Создать отдельные токены и Credentials n8n.
- [ ] Создать schema вида **kompaniya_kod**.
- [ ] Создать таблицы, индексы, функцию поиска и политики доступа.
- [ ] Запретить доступ к schema других компаний.

## 3. Копирование workflow

- [ ] Скопировать клиентский workflow.
- [ ] Скопировать служебный workflow.
- [ ] Указать фиксированную schema компании.
- [ ] Подключить правильные Credentials.
- [ ] Заполнить блок «МЕНЯТЬ ПРИ ВНЕДРЕНИИ».
- [ ] Проверить, что schema не определяется из входного сообщения.

## 4. Загрузка знаний

- [ ] Привести документы к формату Markdown.
- [ ] Назначить постоянные identifikator_dokumenta.
- [ ] Загрузить документы через служебного бота.
- [ ] Проверить отчёты о фрагментах.
- [ ] Выполнить контрольные вопросы.
- [ ] Повторно загрузить изменённый документ и проверить архивирование старой версии.

## 5. Настройка диалога и дашборда

- [ ] Адаптировать системный prompt под компанию.
- [ ] Настроить каналы, этапы и цели.
- [ ] Настроить напоминания.
- [ ] Добавить бренд и логотип.
- [ ] Настроить роли руководителя и разработчика.

## 6. Приёмка

- [ ] Проверить новый диалог по каждому каналу.
- [ ] Проверить конверсии и потерянные диалоги.
- [ ] Проверить уведомления об ошибках.
- [ ] Проверить запрет чужих данных.
- [ ] Сохранить актуальный JSON workflow и документацию в GitHub.
- [ ] Зафиксировать версию внедрения.
