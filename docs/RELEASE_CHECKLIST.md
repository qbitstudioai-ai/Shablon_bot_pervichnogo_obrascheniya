# Проверка перед рабочим запуском

Это критерии будущей приёмки, а не отчёт об уже работающем продукте. Сейчас все рабочие проверки ниже **не выполнены**. Для компании создаётся закрытая копия списка: дата, среда, версия, сценарий, результат и подтверждение без публикации клиентских данных.

ChatGPT готовит проверки и оценивает результат; Павел выполняет действия в интерфейсах по короткой инструкции. Автоматические проверки готовит исполнитель соответствующей задачи. Пропущенный обязательный пункт не считается успешным.

## Установка и права

- [ ] Паспорт содержит проверенные версии n8n, Supabase, PostgreSQL, pgvector, Auth, библиотек обработки и моделей; нет зависимости от недоступной возможности облачного Supabase.
- [ ] Компания и среда определяются серверной конфигурацией, а не входным текстом, параметром браузера или ответом LLM.
- [ ] Отдельные роли n8n и сервера дашборда не владеют таблицами, не имеют BYPASSRLS, прав DDL и доступа к другим компаниям.
- [ ] Выполнена матрица [изоляции](specs/ACCESS_AND_ISOLATION.md): компания A не читает/изменяет B, B не читает/изменяет A; проверены таблицы, функции, векторы, оригиналы и архивы.
- [ ] Входное значение чужой schema, ID документа/диалога, вызов функции с подменённым путём и доступ через браузер не обходят ограничения.
- [ ] Клиентский бот не видит черновики и оригиналы знаний; служебный загрузчик не читает сырые переписки.
- [ ] Секреты не попадают в браузер, публичный Git, экспорт, закреплённые данные нод и диагностические сообщения. Studio, n8n и PostgreSQL защищены серверным доступом.

## Входящие, память и восстановление

- [ ] Для каждого включённого канала подтверждено, когда отправляется успешный ответ на webhook. Принятое событие уже надёжно сохранено либо есть проверенный независимый буфер/восстановление.
- [ ] Отключение БД в момент входа и перезапуск n8n после подтверждения приёма не теряют принятое сообщение. Если стандартный Trigger не обеспечивает это, запуск запрещён до выполнения RT-01.
- [ ] Повтор одного события не создаёт второго сообщения, ответа, заявки или цели.
- [ ] Быстрые сообщения одного человека сохраняются все; обработка последовательна. Сообщения разных людей не получают общую память.
- [ ] Новый вход во время LLM и работник с истёкшей блокировкой не затирают новые данные и не применяют устаревшее решение.
- [ ] После перезапуска восстановлена короткая память. В обычном ответе весь архив не загружается.
- [ ] Возврат в прежнюю подписанную сессию сайта восстанавливает беседу; чужая/поддельная сессия не даёт к ней доступа.
- [ ] Сбой после регистрации исходящего действия, после вызова канала и после подтверждения проверен отдельно. Неизвестный результат видим, не повторяется вслепую.
- [ ] Неподтверждённый ответ не становится сказанной ботом репликой в памяти и не учитывается как отправленный.
- [ ] Сбой CRM не теряет локальную заявку; повтор проверяет стабильный ключ и не создаёт второй лид. Запись на замер подтверждается фактом записи.
- [ ] Ошибка LLM/поиска имеет понятный ограниченный путь восстановления; бот не выдумывает отсутствующую характеристику.

## Диалог и напоминания

- [ ] Телефон, явное намерение и подтверждённая запись создают отдельные цели; телефон сам по себе не закрывает разговор.
- [ ] «Заявка принята, свяжется специалист», завершённая консультация, отказ и передача человеку прекращают автоматическое ожидание.
- [ ] Необязательный вопрос о причине отказа не включает напоминания; «больше не пишите» исключает и этот вопрос.
- [ ] Проверен пример t0 = 14.09 10:00: первое 14.09 10:20, второе 15.09 10:00, потеря не раньше 16.09 10:00.
- [ ] Напоминания не меняют t0; оно появляется только после подтверждённого основного вопроса.
- [ ] Новое сообщение, завершение или передача отменяют задания. Одновременный вход, сохранённый до финальной проверки, предотвращает отправку.
- [ ] Проверена неизбежная граница внешнего API: уже отправляемое напоминание может пересечься с ответом, но продолжения старой цепочки не будет.
- [ ] Просроченные напоминания не отправляются подряд. Задержка второго переносит потерю на 24 часа после фактической отправки.
- [ ] Заблокированный бот, закрытая вкладка, неизвестная отправка и недоступный канал не записываются как подтверждённое молчание клиента после второго напоминания.
- [ ] Возврат после потери создаёт новый диалог и событие возврата; прежняя потеря сохраняется. Благодарность и оценка не создают ложный возврат.
- [ ] Переданный сотруднику диалог не забирается ботом без явного возврата управления.

## Знания и Markdown

- [ ] У каждой компании собственный служебный бот; чужие отправители и поддельный источник события отвергаются.
- [ ] Проверены UTF-8, фактический лимит 5 MiB, YAML без выполнения кода, дубли ключей, неверный ID и структура заголовков.
- [ ] Единицы, отрицания, размеры, таблицы и FAQ не теряются; команды внутри документа не становятся инструкциями системы.
- [ ] Проверены длинная таблица, длинная строка, блок кода и длинный FAQ: без обрезки фактов, с понятной ошибкой при невозможности безопасного деления.
- [ ] Размеры считаются выбранным tokenizer с учётом заголовков и повторяемых частей; метаданные каждого фрагмента принадлежат своему файлу.
- [ ] Неизменённый активный документ — дубль; тот же ID с изменением — новая версия; похожий другой ID не заменяется автоматически.
- [ ] Изменение значимых YAML-полей учитывается. Ошибочная предыдущая попытка не мешает повторить обработку.
- [ ] Три и более последовательных обновления сохраняют несколько архивов без ошибки уникальности.
- [ ] Новый документ до публикации недоступен клиенту; контрольный поиск видит конкретный черновик через отдельный доступ.
- [ ] Ошибка любого пакета embeddings или контрольного вопроса оставляет рабочую версию; без вопросов документ ожидает проверки.
- [ ] Конкурирующие обновления не дают старой задаче перезаписать новый активный документ.
- [ ] Повтор публикации безопасен; ошибка Telegram-отчёта после публикации не отменяет знание.
- [ ] Обычный поиск фильтрует компанию, профиль и активную версию до отбора результатов; архивы и чужие данные отсутствуют.
- [ ] Подобраны top-k/порог по контрольному набору. Изменение модели проверено как отдельная переиндексация, без смешивания несовместимых векторов.

## Дашборд и показатели

- [ ] На фиксированном наборе минимум из 10 учебных пользователей ручной расчёт совпадает с дашбордом: первые обращения 14–18 сентября, старый пользователь с возвратом 16 сентября, цели позже периода, несколько целей одного человека, N = 0.
- [ ] Показаны часовой пояс, включённые границы периода и дата среза. Новые пользователи, вся активность и возвраты не смешаны.
- [ ] Потеря и возврат восстанавливаются на дату среза; достижение цели и последующая потеря могут относиться к одному человеку.
- [ ] Ошибка системы отличима от предполагаемой ошибки LLM; реакция по тексту обозначена как оценка с доказательством, а пользовательский отзыв — как ответ человека.
- [ ] Руководитель видит только свою компанию и разрешённые переписки; админ-панель доступна только Павлу, включая прямые HTTP-запросы.
- [ ] Логотип и оформление меняются без редактирования CORE; опасный файл/HTML не исполняется в интерфейсе.
- [ ] Учебные сообщения и служебные загрузки исключены из клиентских метрик по проверяемому признаку.

## Эксплуатация, резервирование и выпуск

- [ ] Рабочие и тестовые Telegram-токены различаются; по каждому токену один активный вход. Проверка Trigger не перезаписывает рабочий webhook.
- [ ] Шаблон содержит безопасные экспорты, версию конфигурации, миграции, инструкции применения и сведения о совместимости.
- [ ] Определены сроки хранения чатов, короткой памяти, файлов знаний, архивов, журналов n8n и копий; очистка не удаляет нужные связи и неподтверждённые действия.
- [ ] Резервируются общая БД с Auth, роли/права и расширения, база n8n, ключ шифрования Credentials, конфигурация установки и файлы логотипов. Секретные копии хранятся вне публичного Git.
- [ ] Восстановление реально проверено в отдельной среде. Известны допустимая потеря данных и время восстановления; восстановление одной компании не затирает остальных.
- [ ] После восстановления сверены новые внешние события и отправки за время сбоя. Старое задание не отправляет повторно сообщение или CRM-заявку только потому, что копия БД отстала.
- [ ] Внешняя проверка обнаруживает остановку n8n/БД, а повторные ошибки не создают лавину Telegram-сообщений. Есть путь оповещения при недоступности самого Telegram.
- [ ] Зафиксированы и проверены ожидаемая нагрузка, длина очереди, время ответа и бюджет LLM/embeddings; обещания скорости основаны на измерении.
- [ ] Перед рабочим действием известны резервная копия, последовательность переключения, критерии остановки и совместимый откат. Смена Git-версии сама по себе не откатывает БД.
- [ ] Павел разрешил конкретное переключение production; после включения проверены реальное обращение, сохранение, ответ, метрика и уведомление.
- [ ] Частный паспорт содержит фактически применённые версии, время, результат проверки и ответственного.

Невыполненные проверки надёжного приёма, изоляции, восстановления или единственного webhook запрещают выпуск. Срок наблюдения после запуска и его пороги записываются в паспорт до переключения.
