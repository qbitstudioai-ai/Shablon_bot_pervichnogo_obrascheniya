# Одна задача — одна сессия

Проект ChatGPT называется `Shablon_bot_pervichnogo_obrascheniya`. Новая сессия открывается в том же проекте. Инструкции проекта помогают ориентироваться, но актуальные правила и состояние читаются с GitHub.

ChatGPT сам предлагает переход после законченной небольшой задачи. Если контекст заканчивается раньше, допустима передача незавершённой задачи с точной остановкой. Нельзя обещать безошибочное продолжение только благодаря памяти чата.

## Карточка перед началом

Карточка находится в сообщении начала работы; выбранная задача и статус — в [состоянии](PROJECT_STATE.md) и активном плане.

| Поле | Что записать |
|---|---|
| ID | Постоянный номер из плана |
| Цель | Один конкретный результат |
| Исполнитель | ChatGPT, помощник в VSCode; ручные действия Павла отдельно |
| Условия начала | Зависимости, доступы, разрешение на вид работы |
| Обязательное чтение | Основные документы задачи |
| Объём | Файлы и среды, которые можно изменять |
| Готовность | Наблюдаемый результат и существенная проверка |
| Состояние | Что уже сделано; где остановились |
| Следующий шаг | Только одно действие или одна задача |

Не начинай реализацию, если разрешена только документация. Не спрашивай повторное разрешение на уже порученную работу.

## Завершение сессии

1. Проверь результат по критерию задачи.
2. Обнови активный план и PROJECT_STATE: факт, проверка, непройденное, препятствие, следующий ID.
3. Сохрани файлы и убедись, что commit доступен в нужной ветке GitHub.
4. Подготовь короткий итог и блок передачи ниже.
5. Предложи Павлу открыть новую сессию и скопировать блок. Полный старый чат переносить не нужно.

Результаты с персональными данными в публичную передачу не включаются. При продолжении закрытого внедрения указывается безопасное местонахождение частного паспорта, без токенов и паролей.

## Готовый формат передачи

```text
ПЕРЕДАЧА В НОВУЮ СЕССИЮ
Проект: Shablon_bot_pervichnogo_obrascheniya
Репозиторий: https://github.com/qbitstudioai-ai/Shablon_bot_pervichnogo_obrascheniya
Ветка: <ветка>
Проверенный commit: <полный SHA>
Режим: <только документация / разрешённая задача реализации / внедрение компании>
Компания и среда: <код и test/prod или не применимо>

Задача: <ID, завершена / в работе / пауза>
Результат: <1–3 факта и файлы>
Проверено: <сценарий и результат>
Не проверено: <конкретно>
На сервере: <что и где применено либо не применялось>
Препятствия и незавершённые действия: <нет / точное состояние>
Следующая одна задача: <ID и цель>

Прочитай README.md, docs/CHATGPT_INSTRUCTIONS.md,
docs/PROJECT_STATE.md, docs/SESSION_HANDOFF.md, активный план
и основные документы следующей задачи.
Сверь указанный SHA с текущей веткой и учти более новые изменения.
Продолжай с зафиксированного места; не повторяй выполненные действия.
```

Поля заполняются фактическими сведениями. «Тесты прошли» без указания, какие именно, недостаточно.

## Если задача прервалась

Сохрани безопасную контрольную точку: файлы, состояние операции и последний подтверждённый результат. Укажи, был ли внешний запрос уже отправлен, получен ли ответ и можно ли повторять действие.

Например: «Импорт не выполнялся; JSON только подготовлен» или «Запрос к CRM отправлен, подтверждение не получено; сначала проверить запись по ключу, не создавать повторно».

Новый чат сначала восстанавливает факты. Неоднозначное внешнее действие не запускается повторно на основании отсутствия сообщения старого чата.

## Задание помощнику в VSCode

```text
Задача <ID>: <один результат>.
Репозиторий: <URL>; ветка: <имя>; исходный SHA: <значение>.
Прочитай: <файлы>.
Измени: <точный объём>.
Критерии готовности: <наблюдаемые результаты>.
Выполни проверки: <существенные проверки>.
Обнови: <основной документ>, активный план, docs/PROJECT_STATE.md.
Сохрани commit и push в разрешённую ветку.
Выпуск на сервер: <не входит / явно разрешённый объём>.
Верни: файлы, результаты проверок, что не проверено,
что применено на сервере, commit SHA, препятствия.
```

ChatGPT проверяет этот отчёт чтением GitHub. Павел получает понятные действия в интерфейсах и готовые файлы, а не задание программировать.

## Проверка передачи

Передача пригодна, если новая сессия может определить текущий режим, один следующий ID, обязательные файлы, уже выполненные действия и то, что пока нельзя считать проверенным. При расхождении сначала читается актуальный PROJECT_STATE и история изменений, затем уточняется только остающаяся существенная неопределённость.
