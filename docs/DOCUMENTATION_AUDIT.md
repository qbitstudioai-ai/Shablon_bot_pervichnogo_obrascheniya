## Существенные уточнения

Нельзя гарантировать изоляцию названием schema или скрытой кнопкой. Ограничения должны действовать при прямом обращении с рабочими Credentials.

Нельзя удалить действующие знания до подготовки замены. Неизменённый активный файл — дубль, а изменённый документ с тем же постоянным ID — новая версия.

Нельзя запретить клиенту писать в личный чат Telegram средствами restrictChatMember: этот метод относится к супергруппам. Сайт может ограничить поле ввода, но сервер всё равно должен принимать повторы и быстрые сообщения.

Нельзя полагаться на историю исполнений или Simple Memory как единственную долговременную память. В очередь n8n нельзя просто перенести Simple Memory без учёта ограничений разных работников.

Нельзя объявить webhook надёжным только потому, что после Trigger расположена нода записи в БД. Момент подтверждения входа проверяется в PRE-01 и RT-01; до доказанного сохранения/восстановления production не допускается.

Эти уточнения исправляют план реализации, не утверждают, что сервер уже настроен.

## Официальные источники

Проверены при подготовке 20.09.2026. Приведены для обоснования ограничений; точные версии установки фиксируются позже в паспорте.

- [Supabase self-hosting](https://supabase.com/docs/guides/self-hosting) — серверная установка.
- [PostgreSQL: schema и права](https://www.postgresql.org/docs/current/ddl-schemas.html) — schema не является самостоятельной границей доступа.
- [Supabase: RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) — права, политики и привилегированный обход.
- [n8n: Postgres](https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.postgres/) — выбранный способ обращения workflow к ограниченной роли БД.
- [Telegram: setWebhook](https://core.telegram.org/bots/api#setwebhook) и [restrictChatMember](https://core.telegram.org/bots/api#restrictchatmember) — доставка обновлений и границы управления вводом.
- [n8n: ограничения Telegram Trigger](https://docs.n8n.io/integrations/builtin/trigger-nodes/n8n-nodes-base.telegramtrigger/common-issues/) — конфликт тестового и рабочего webhook одного токена.
- [n8n: Simple Memory](https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.memorybufferwindow/) — ограничения памяти в queue mode.
- [n8n: Default Data Loader](https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.documentdefaultdataloader/) — деление по умолчанию и особенности выражений sub-node; они не заменяют наш структурный контракт.
- [n8n: Code](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.code/) — подключение библиотек self-hosted установки требует явной настройки.
- [Supabase: vector columns](https://supabase.com/docs/guides/ai/vector-columns) и [semantic search](https://supabase.com/docs/guides/ai/semantic-search) — векторные данные, размерность и поиск.
- [n8n: monitoring](https://docs.n8n.io/deploy/host-n8n/keep-n8n-running/monitor-n8n/) и [export/import](https://docs.n8n.io/build/manage-workflows/export-and-import/) — эксплуатационные проверки и обращение с экспортами.

Числа 5 MiB, 600/800/100 токенов, короткая память и политика задержек — принятые стартовые решения проекта, а не универсальные требования этих продуктов.
