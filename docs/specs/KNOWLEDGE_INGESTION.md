# Загрузка базы знаний

Статус: предварительная архитектура. Правила очистки и чанкинга будут спроектированы следующим блоком.

## Цель

Павел загружает Markdown через служебного Telegram-бота. Система проверяет файл, готовит его для поиска, публикует новую версию базы знаний и сообщает результат.

## Принятое направление

- первоначальный формат — `.md`;
- вход — отдельный служебный Telegram-бот;
- доступ — только разрешённые Telegram user ID;
- обработка — центральный служебный workflow n8n;
- хранилище — Supabase выбранной компании;
- результат — подтверждение или понятная ошибка в Telegram;
- тот же бот отправляет безопасные системные уведомления.

Служебный workflow отделён от production-workflow общения с клиентами.

## Предварительный процесс

1. Павел выбирает компанию или schema.
2. Отправляет Markdown-файл.
3. Бот показывает имя, размер и выбранное назначение.
4. Павел подтверждает загрузку.
5. Система проверяет формат и контрольную сумму.
6. Оригинал сохраняется как новая версия документа.
7. Текст очищается от технического мусора.
8. Документ делится на смысловые чанки.
9. Для чанков создаются embeddings.
10. Выполняются контрольные проверки.
11. Новая версия публикуется только после успешной обработки.
12. Павел получает отчёт.

## Требования

- повторная загрузка одинакового файла не создаёт дубликат;
- новая версия не удаляет предыдущую до успешной публикации;
- ошибочная обработка не повреждает действующую базу;
- можно архивировать документ и перестроить его чанки;
- у каждого чанка известны документ, версия, раздел и порядок;
- загрузка в одну компанию не изменяет данные другой;
- уведомления не содержат секретов.

## Что нужно спроектировать следующим блоком

- допустимая структура Markdown;
- что считается мусором;
- правила обработки таблиц, списков и заголовков;
- стратегия чанкинга для разных типов документов;
- размер чанка и перекрытие;
- обязательные метаданные;
- модель embeddings;
- контроль качества поиска;
- обновление и удаление документов;
- выбор компании в Telegram;
- хранение оригинального файла;
- пределы размера файла;
- команды и подтверждения служебного бота.

## Критерий готовности будущей реализации

Тестовый Markdown загружается через Telegram, индексируется и находится по контрольным вопросам. При ошибке действующая версия базы знаний продолжает работать.
