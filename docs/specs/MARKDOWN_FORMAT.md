# Требования к Markdown-файлам базы знаний

## 1. Минимальный формат

Файл должен:

- иметь расширение **.md**;
- быть сохранён в UTF-8;
- содержать служебный блок YAML в начале;
- иметь один заголовок H1;
- не содержать пароли, токены и персональные данные клиентов.

Пример:

~~~markdown
---
identifikator_dokumenta: okna_plastikovye
nazvanie: Пластиковые окна
tip_dokumenta: harakteristiki
versiya_istochnika: "1.0"
data_obnovleniya: "2026-09-19"
---

# Пластиковые окна

## Где применяются

Текст раздела.

## Характеристики

### Модель Alfa 70

- Монтажная глубина: 70 мм
- Количество камер: 5
~~~

## 2. Обязательные поля

| Поле | Правило |
|---|---|
| identifikator_dokumenta | Постоянное имя документа: латиница, нижний регистр, snake_case |
| nazvanie | Понятное русское название |
| tip_dokumenta | Значение из согласованного списка |

Дополнительные поля:

- **versiya_istochnika** — версия документа у компании;
- **data_obnovleniya** — дата обновления источника.

Начальный список типов:

- **opisanie**
- **harakteristiki**
- **instrukciya**
- **faq**
- **usloviya**
- **politika**

Новый тип добавляется в документацию до использования.

## 3. Заголовки

- H1 — название документа, строго один раз.
- H2 — крупный самостоятельный раздел.
- H3 — подраздел.
- Нельзя перескакивать с H1 сразу на H3.
- Заголовок должен описывать содержание, а не называться «Разное» или «Информация».
- В FAQ каждый вопрос оформляется отдельным H2 или H3, а ответ идёт сразу под ним.

## 4. Что полезно сохранять

- точные характеристики и единицы измерения;
- названия моделей и артикулы;
- ограничения и исключения;
- вопросы вместе с ответами;
- заголовки таблиц;
- ссылки, если без них теряется смысл;
- условия цены с датой и областью действия.

## 5. Чего не должно быть

- повторяющегося меню и навигации сайта;
- рекламных лозунгов без фактов;
- пустых заголовков;
- скопированных кнопок и элементов интерфейса;
- HTML script/style;
- паролей, API-ключей и токенов;
- переписок с реальными клиентами;
- нескольких разных тем без понятных разделов.

## 6. Идентификатор и имя файла

Имя файла можно менять. Поле **identifikator_dokumenta** менять нельзя, пока это тот же логический документ.

Если содержание обновилось:

- оставить прежний **identifikator_dokumenta**;
- изменить текст;
- при необходимости изменить **versiya_istochnika** и **data_obnovleniya**;
- отправить файл служебному боту повторно.

Если это другой документ, ему нужен новый идентификатор. Похожесть текста не используется для автоматической замены.
