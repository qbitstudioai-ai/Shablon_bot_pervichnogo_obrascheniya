# Надёжность, память и восстановление

## Сообщения нельзя защищать только блокировкой интерфейса

В личном Telegram-чате бот не управляет кнопкой отправки клиента. Метод ограничения участников относится к супергруппам. Для других внешних каналов такая возможность не предполагается без подтверждения API.

На собственном сайте можно отключать повторное нажатие и показывать «Бот отвечает», сохраняя черновик и снимая блокировку по тайм-ауту. Это удобство интерфейса, а не гарантия: несколько вкладок и повтор HTTP всё равно возможны.

Система принимает и сохраняет входящие, а обработку одного диалога выполняет последовательно. Короткие сообщения можно собрать в пакет: стартово 2 секунды тишины, максимум 5 секунд с первого входа. Каждое исходное сообщение остаётся отдельной записью.

## Где хранится память

Надёжный источник — одна PostgreSQL-база серверного Supabase. В schema компании есть:

- soobshcheniya — архив исходных сообщений и статусов;
- pamyat_dialoga — рабочее резюме, подтверждённые факты и короткое окно обезличенных сообщений.

n8n читает одну небольшую запись памяти и необработанные входящие; весь архив перед каждым ответом не загружается. Стартовое окно — последние 20 сообщений плюс резюме в пределах бюджета контекста выбранной модели. Длина проверяется токенизатором; предел бюджета будет указан в паспорте версии.

Неподтверждённый исходящий текст не записывается в память как уже услышанный клиентом. Резюме обновляется с указателем obrabotano_do_id и версией; его содержание не заменяет исходные доказательства целей.

Хранить единственную память в RAM n8n, Simple Memory или истории выполнений нельзя. После перезапуска/перехода между работниками такой механизм не гарантирует продолжение. Simple Memory, в частности, не подходит для queue mode.

Кэш допускается позже по измерениям задержки; он не становится источником истины. При потере/устаревании рабочей памяти выполняется ограниченное восстановление из обезличенной истории, а не выдумывание контекста. Это исключение к обычному чтению короткой памяти.

Закрытие вкладки не удаляет серверную память. Идентичность сайта хранится в защищённой подписанной сессии; при её удалении или смене устройства связь без авторизации восстановить нельзя. Не использовать одинаковый анонимный ID для всех посетителей. Для нового диалога вернувшегося человека передаются краткие релевантные сведения прошлого; старые цены и наличие проверяются по текущим знаниям.

## Надёжный вход и очередь

Входное событие, сообщение и задание сохраняются до подтверждения приёма. Проверка поведения Trigger обязательна: ранний HTTP 200 без долговечной записи не является выполнением требования.

Если Supabase недоступен до сохранения, адаптер возвращает повторяемую ошибку, где канал это поддерживает. Если Trigger не позволяет управлять подтверждением, до production реализуется долговечный входной буфер вне рабочей БД либо подтверждённая сверка с историей канала. Выбор и результат фиксируются PRE-01/RT-01. Обычное успешное выполнение Trigger не доказывает отсутствие потери.

Очередь хранится в PostgreSQL, не в длинном ожидании одного выполнения n8n. Задание имеет статус, число попыток, срок следующей попытки, срок аренды и номер владения.

Работник атомарно забирает задание и получает ограниченную по времени аренду. На диалог допускается один обработчик. Долгий вызов LLM/канала не держит открытую SQL-транзакцию: аренда продлевается, запись результата разрешена только текущему владельцу с актуальной версией. Задание с истёкшей арендой подхватывается после сверки завершённых действий.

Новый вход сохраняется даже во время ответа модели. До отправки проверяется версия состояния: устаревший ответ пересматривается или новые сообщения обрабатываются следующим пакетом. Отказ/передача имеет приоритет. Нельзя отвечать из старого состояния и одновременно перезаписывать новые данные.

## Исходящие действия

Очередь исходящих действий хранит отправку сообщения, операцию CRM или уведомление отдельно от задания генерации.

Статусы действий:

| Код | Смысл |
|---|---|
| zaplanirovano | Намерение сохранено, внешнего запроса ещё нет |
| v_rabote | Действие забрал работник |
| podtverzhdeno | Есть положительный ответ или надёжная сверка |
| povtor | Есть явная временная ошибка; повтор безопасен |
| neizvestno | Запрос мог выполниться, подтверждения нет |
| otmeneno | Действие устарело до отправки |
| oshibka | Постоянная ошибка/исчерпаны безопасные повторы |

Порядок: сохранить намерение → вызвать API → сохранить подтверждение → выполнить зависимое изменение состояния. Зависимые изменения в БД выполняются одной транзакцией с защитой от повторного применения.

Ключ действия строится из события/диалога, вида операции и номера логического ответа, а не из нового случайного ID при каждом повторе.

Если отправка успешна, а запись подтверждения не удалась, действие остаётся для сверки. Нельзя заново генерировать и отправлять тот же ответ вслепую. Где канал поддерживает idempotency key или чтение истории — используется это. Где надёжной сверки нет — статус neizvestno, безопасное уведомление оператору и приостановка зависимых действий. Гарантия «ровно один раз» для любого внешнего API не обещается.

Технический индикатор «печатает» не считается ответом/целью, не запускает напоминания. Если его API недоступен, бизнес-обработка продолжается.

## CRM и приём заявки

Локальная заявка с внешним ключом сохраняется до передачи в CRM. Сбой CRM не стирает сообщение или заявку. Операция повторяется отдельно; бизнес-статус и технический статус синхронизации различаются.

Можно сказать «заявка принята» после её долговечной локальной регистрации и постановки задачи назначенному сотруднику, если такой резервный маршрут включён при внедрении. Нельзя говорить «записаны на замер» до подтверждения конкретной записи.

CRM-адаптер ищет существующую запись по стабильному ключу перед повторным созданием. При отсутствии безопасного механизма работает сценарий сверки, а не бесконечный повтор.

## Ошибки и уведомления

- Временные ошибки LLM/БД/CRM: ограниченные повторы с увеличением паузы и Retry-After; пределы задаются в паспорте версии.
- Напоминания имеют специальные сроки из [жизненного цикла](CONVERSATION_LIFECYCLE.md).
- Сбой анализа качества не останавливает клиентский ответ; результат анализа помечается как отсутствующий.
- Сбой поиска не разрешает придумывать характеристики: уточнение/передача человеку.
- Ошибка одного необязательного сервиса не должна приводить к незаметному исчезновению обращения.

sistemnye_sobytiya хранит безопасные данные: компонент, ID операции, время, уровень, код ошибки, состояние оповещения. Повторяющиеся ошибки группируются; уведомления об одном инциденте ограничиваются и завершаются сообщением о восстановлении.

Если сама Supabase недоступна, ошибка сохраняется в защищённом журнале процесса/сервера вне неё. Если n8n остановлен, внешний монитор проверяет доступность и отсутствие ожидаемых сигналов. Уведомление в этом случае отправляет монитор напрямую, а не неработающий workflow.

Если Telegram тоже недоступен, нужен резервный канал оповещения Павла; его выбор является обязательным пунктом подготовки выпуска. Ошибка отправки уведомления не запускает рекурсивную рассылку об этой же ошибке.

## Пределы нагрузки и данных

Внедрение фиксирует допустимое число одновременных диалогов, тайм-аут ответа модели, предел очереди, лимиты запросов/стоимости и сигнал о задержке. При перегрузке сообщения остаются в очереди; система не запускает неограниченные вызовы LLM.

Исходные переписки, обезличенная память, оригиналы знаний, архивные версии, журналы n8n и резервные копии имеют явные сроки хранения и правила удаления. Сроки выбираются Павлом для компании до production. Удаление данных распространяется на производные память/векторы/кэш; сроки вытеснения из резервных копий документируются. Это эксплуатационные требования, не юридическое заключение.

Основания: [Telegram restrictChatMember](https://core.telegram.org/bots/api#restrictchatmember), [Simple Memory n8n](https://docs.n8n.io/integrations/builtin/cluster-nodes/sub-nodes/n8n-nodes-langchain.memorybufferwindow/), [Postgres-нода](https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-base.postgres/), [контроль доступности n8n](https://docs.n8n.io/deploy/host-n8n/keep-n8n-running/monitor-n8n).
