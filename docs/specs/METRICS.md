# Метрики руководителя

Нормативные определения v0.2. Показатели считаются по сохранённым событиям, а не по впечатлению LLM. Состав админ-панели находится отдельно в [DASHBOARD_ADMIN.md](DASHBOARD_ADMIN.md).

## Период и знаменатель

Уточнение Павла трактуется буквально: в основную конверсию входят **все известные пользователи, чьё первое обращение к боту этой компании произошло в выбранном периоде**. Не только ответившие, оставившие телефон или дошедшие до цели.

Для периода 14.09.2026–18.09.2026 включительно отбирается первое обращение от 14.09 00:00 до 19.09 00:00, не включая последнюю границу, в часовом поясе компании. Границы переводятся в UTC. В интерфейсе показатель называется «Конверсия пользователей, впервые обратившихся за период».

Человек, впервые написавший 13.09 и вернувшийся 16.09, не становится новым пользователем этого периода. Он учитывается в активности и возвращениях. Так общий охват не смешивается с конверсией первого обращения.

**C** — множество этих пользователей; **N** — его размер. Боты, внутренние проверки, служебные сотрудники и тестовая среда исключаются по явным признакам, а не по субъективному мнению о качестве лида.

## Дата результата

Все отчёты возвращают **na_moment** — дату/время, до которой учтены события. По умолчанию это момент построения отчёта. Рядом с историческим периодом написано «Результаты по состоянию на …».

Цель, достигнутая позже периода, учитывается для C, если она достигнута до na_moment. Поэтому незавершённая группа со временем меняется. Отдельный режим «на конец периода» ограничивает результаты концом периода. Эти режимы нельзя смешивать без подписи.

## Конверсии

Для каждой цели: число уникальных пользователей из C с подтверждённым событием этой цели до na_moment / N × 100%.

Цели: telefon_poluchen, namerenie_zakazat, zamer_podtverzhden. Повтор одной цели у человека не увеличивает числитель. Общая конверсия — объединение пользователей с хотя бы одной целью, не сумма процентов.

Цель не равна финальному успеху продажи. Пользователь может оставить телефон, а потом отказаться; он сохранит конверсию в телефон и получит текущий результат отказа. Поэтому конверсия и текущие потери не являются частями одной суммы 100%.

При N=0 показывается «нет данных» (null), а не 0% как якобы измеренный результат.

## Активность и возвращения

| Показатель | Правило |
|---|---|
| Все обратившиеся за период | Уникальные известные пользователи с хотя бы одним входящим сообщением в периоде, включая старых |
| Первые обращения | N |
| Начатые диалоги | Число новых диалогов периода |
| Входящие сообщения | Новые сообщения клиентов по времени приёма, без повторов webhook |
| Сообщения бота | Уникальные подтверждённые исходящие по фактическому времени отправки |
| Основные ответы / напоминания / технические сообщения | Отдельные виды; не скрывать состав общего числа |
| Вернувшиеся пользователи | Уникальные пользователи с событием vozvrat после прошлой потери в периоде |
| События возврата | Все такие события; один человек может вернуться несколько раз |
| Конверсия после возврата | Пользователи из группы возвратов периода с целью в диалогах, начавшихся соответствующими возвратами, до na_moment / размер этой группы |
| Целевые события периода | Факты целей по их дате, независимо от даты первого обращения; отдельно от конверсии C |

Определение возврата и метки — в [CONVERSATION_LIFECYCLE.md](CONVERSATION_LIFECYCLE.md). Восстановление старой вкладки/повтор события без нового содержательного обращения не является возвратом.

## Потери без двойного счёта

Текущий результат пользователя определяется последним релевантным диалогом на na_moment.

- Текущий отказ: пользователь из C, последний диалог закрыт как otkaz.
- Текущая потеря без ответа: из C, последний диалог закрыт как net_otveta.
- Общая текущая потеря: объединение этих двух множеств / N × 100%.
- Вернувшийся и снова общающийся человек исключается из текущей потери, но факт прошлой потери сохраняется.
- Техническое завершение, передача человеку и справочное завершение не являются потерей.
- «Когда-либо были потеряны» — отдельный исторический показатель, не подмена текущего результата.

Два диалога одного пользователя не дают два человека в числителе. Суммировать числа диалогов и делить на число людей запрещено.

Пример проверки: N=10; один человек сначала потерян, затем вернулся и оставил телефон. Конверсия в телефон — 10%; его текущая потеря — 0%; исторически потерянных — 1; вернувшихся — 1 в периоде события возврата.

## Каналы, этапы и идентичность

В основной конверсии фильтр канала означает канал первого обращения. В показателях активности — канал конкретных сообщений/диалогов. В UI эти фильтры подписываются, не меняют смысл молча.

Один человек в разных каналах считается разными известными пользователями до подтверждённого связывания. Имя и похожий текст не основание объединения. В v1 автоматическое межканальное объединение не выполняется; будущая процедура должна сохранять историю и пересчитать показатели явно.

Для этапов показываются входы, уникальные пользователи, выходы/переходы, цели, отказы, молчание и длительность. Этапы не обязательно линейны: возможны возвраты и пропуски. Точка потери — последний подтверждённый этап перед событием потери; история этапов не заменяется текущим значением.

## Качество и реакция

Объективные показатели: ошибки доставки/LLM/CRM/БД, повторы, задержка первого и последующих ответов, размер очереди, передачи человеку.

Гипотезы модели: вопрос без ответа, ответ без опоры на знания, непонимание потребности, повтор, игнорирование возражения, отрицательная реакция, пробел знаний. Сохраняются доказательные ID сообщений, объяснение, уверенность, версия модели/prompt и подтверждение человеком.

Реакции: положительная, нейтральная, отрицательная, раздражение, недоверие, заинтересованность. Это оценка текста, не установленное внутреннее состояние клиента.

Явная обратная связь: оценка (в v1 шкала 1–5), текст, дата, диалог, канал. Одна текущая оценка диалога на пользователя; исправления сохраняются в истории. Запрос отзыва не запускает продажи и напоминания о потребности.
