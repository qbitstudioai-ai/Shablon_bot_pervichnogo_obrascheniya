# Метрики и дашборд руководителя

## Назначение

Документ задаёт смысл показателей. SQL и интерфейс должны использовать эти определения, чтобы разные экраны не считали одно и то же по-разному.

## Базовые понятия

- **Пользователь** — уникальная известная личность или идентификатор внутри одного канала.
- **Новый пользователь периода** — пользователь, чьё первое обращение попало в выбранный период.
- **Диалог** — отдельная последовательность сообщений с началом и результатом.
- **Целевое событие** — подтверждённый полезный результат.
- **Потеря** — явный отказ или закрытие после отсутствия ответа.
- **Активный диалог** — диалог, который ещё нельзя считать результатом или потерей.

Один человек в разных каналах считается разными пользователями, пока система не сможет безопасно связать их по подтверждённым данным.

## Главные показатели

| Показатель | Определение |
|---|---|
| Новые пользователи | Уникальные пользователи с первым обращением в периоде |
| Диалоги | Диалоги, начатые в периоде |
| Входящие сообщения | Сообщения пользователей, полученные в периоде |
| Ответы бота | Успешно отправленные сообщения бота в периоде |
| Получен телефон | Пользователи периода с событием `phone_received` |
| Намерение заказать | Пользователи периода с событием `order_intent` |
| Запись на замер | Пользователи периода с событием `measurement_booked` |
| Явные отказы | Пользователи периода с результатом `declined` |
| Нет ответа | Пользователи периода с результатом `lost_no_response` |
| Активные | Пользователи периода без закрытого результата |

## Конверсии

Для выбранного периода используется когорта новых пользователей: знаменатель — пользователи, впервые написавшие в этот период.

```text
Конверсия в получение телефона =
пользователи когорты с phone_received
÷
все новые пользователи когорты × 100%
```

Аналогично рассчитываются:

- конверсия в явное намерение заказать;
- конверсия в запись на замер;
- общая конверсия — достигнута хотя бы одна целевая точка.

Недавние периоды могут содержать незавершённые диалоги. Поэтому рядом показывается доля активных пользователей и предупреждение о незавершённой когорте.

Отдельно показывается количество целевых событий, произошедших в самом выбранном периоде, даже если пользователь пришёл раньше.

## Потери

```text
Явный отказ =
declined ÷ все новые пользователи × 100%
```

```text
Потеря без ответа =
lost_no_response ÷ все новые пользователи × 100%
```

```text
Общая потеря =
(declined + lost_no_response)
÷ все новые пользователи × 100%
```

Активные диалоги не включаются в число потерянных.

## Воронка этапов

Для каждого этапа показываются:

- сколько пользователей вошло;
- сколько перешло дальше;
- сколько достигло цели;
- сколько отказалось;
- сколько перестало отвечать;
- среднее и медианное время на этапе.

Точка потери определяется по последнему подтверждённому этапу до закрытия диалога.

Отсутствие ответа не доказывает ошибку бота. На экране это называется «потеря без ответа», а не «бот потерял клиента по своей вине».

## Каналы

Для Telegram, Авито, сайта, VK, MAX и других каналов показываются:

- новые пользователи;
- количество диалогов;
- целевые события;
- конверсия;
- явные отказы;
- потери без ответа;
- среднее время первого ответа;
- технические ошибки доставки.

## Качество диалогов

### Объективные признаки

- сообщение не доставлено;
- ошибка LLM;
- ошибка CRM;
- ошибка Supabase;
- повторная отправка;
- превышение времени ответа;
- передача человеку.

### Аналитическая оценка

Отдельный анализ может находить:

- вопрос без ответа;
- возможный ответ не по базе знаний;
- повторение;
- непонимание потребности;
- игнорирование возражения;
- преждевременную продажу;
- отрицательную реакцию;
- пробел базы знаний.

Это предположение модели. Сохраняются доказательный фрагмент, объяснение, уверенность, версия модели и подтверждение человеком.

## Реакция и обратная связь

Автоматическая реакция может быть:

- положительная;
- нейтральная;
- отрицательная;
- раздражение;
- недоверие;
- заинтересованность.

Явная обратная связь хранится отдельно:

- оценка;
- текст;
- дата;
- диалог;
- канал.

Прямая оценка пользователя надёжнее автоматического определения реакции.

## Разделы дашборда

1. Общая картина.
2. Конверсии и потери.
3. Воронка этапов.
4. Каналы.
5. Качество работы бота.
6. Диалоги с фильтрами.
7. Обратная связь.
8. Техническое состояние для Павла.

## Фильтры

Минимальный набор:

- период;
- канал;
- этап;
- результат;
- целевое событие;
- причина отказа;
- наличие ошибки;
- оценка пользователя.

## Админ-панель Павла

Первая версия позволяет настраивать:

- название компании;
- логотип;
- цвета;
- часовой пояс;
- подписи этапов;
- порядок этапов;
- видимые разделы;
- период по умолчанию.

Она не управляет Credentials, prompts, CRM или CORE.
