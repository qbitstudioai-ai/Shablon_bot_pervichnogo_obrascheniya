# Жизненный цикл диалога

## Назначение

Документ объясняет, как начинается, продолжается и завершается диалог, когда отправляются напоминания и как определяется потеря пользователя.

## Три независимых понятия

### Этап диалога

Что бот делает сейчас:

- приветствие;
- выявление потребности;
- презентация;
- отработка возражения;
- запись на замер;
- передача человеку.

### Целевое событие

Полезный результат, достигнутый в любой момент:

- получен телефон;
- пользователь явно хочет заказать;
- пользователь записан на замер.

Целевые события не обязаны происходить строго по порядку.

### Результат диалога

Чем закончился или в каком состоянии находится разговор:

- активен;
- ожидает ответа пользователя;
- передан человеку;
- достигнута цель;
- явный отказ;
- потерян без ответа;
- технически прерван.

## Основные статусы

| Статус | Значение |
|---|---|
| `active` | Бот или пользователь сейчас ведёт диалог |
| `waiting_user` | Бот задал вопрос и ожидает ответ |
| `followup_1_sent` | Отправлено первое напоминание |
| `followup_2_sent` | Отправлено второе напоминание |
| `handoff` | Диалог передан человеку |
| `converted` | Достигнуто хотя бы одно настроенное целевое событие |
| `declined` | Пользователь явно отказался |
| `lost_no_response` | Пользователь не ответил после всей цепочки |
| `technical_failure` | Продолжение невозможно из-за технической ошибки |

Точный набор кодов будет утверждён вместе с SQL. Смысл статусов уже зафиксирован.

## Начало диалога

Новый диалог создаётся при первом сообщении пользователя, если нет подходящего активного диалога.

Сохраняются:

- пользователь и идентификатор канала;
- канал и диалог источника;
- время первого сообщения;
- исходный текст;
- обезличенный текст;
- уникальный идентификатор события.

## История этапов

Текущий этап хранится для быстрого отображения, но каждое изменение дополнительно записывается как отдельное событие:

```text
предыдущий этап
новый этап
время
причина перехода
кто определил переход
уверенность модели
```

История нужна, чтобы строить воронку и находить места потери.

## Напоминания

Напоминание создаётся только после сообщения бота, которое действительно требует ответа.

### Последовательность

1. Через 20 минут без ответа — напоминание №1.
2. Через 24 часа без ответа — напоминание №2.
3. Через 24 часа после напоминания №2 — статус `lost_no_response`.

Каждое время рассчитывается и сохраняется в Supabase. n8n по расписанию выбирает действия, срок которых наступил.

### Отмена

Любой новый ответ пользователя:

- отменяет ожидающие напоминания;
- возвращает диалог в активное состояние;
- продолжает обработку с сохранённым контекстом.

### Ограничения каналов

Отложенное сообщение отправляется только если адаптер канала поддерживает его и имеются необходимые права. Например, после закрытия страницы сайта невозможно продолжить разговор без другого разрешённого способа связи.

Неудачная отправка не считается отправленным напоминанием. Она записывается как техническое событие.

## Явный отказ

Явным отказом считается прямое сообщение пользователя о том, что предложение неинтересно или потребность отсутствует.

Бот может задать один короткий необязательный вопрос о причине. После ответа или отказа отвечать диалог закрывается.

Причины:

- цена;
- нет потребности;
- не подходит предложение;
- выбран конкурент;
- решение отложено;
- недоверие;
- не подходят условия или регион;
- другое;
- причина не указана.

Если пользователь не назвал причину, LLM не должна её придумывать.

## Возобновление

Пользователь со статусом `declined` или `lost_no_response` может вернуться.

Старая история не удаляется. Система:

- возобновляет подходящий диалог или создаёт новый;
- сохраняет факт возврата;
- отменяет прежний итог только для текущего состояния;
- оставляет старое событие потери для исторической аналитики.

## Проверки готовности

- повторный вход не создаёт дубликат сообщения;
- ответ отменяет оба напоминания;
- первое напоминание не отправляется раньше 20 минут;
- второе не отправляется раньше 24 часов;
- потеря не фиксируется раньше чем через 24 часа после второго напоминания;
- явный отказ и отсутствие ответа считаются отдельно;
- неудачная отправка записывается как ошибка;
- вернувшийся пользователь может продолжить диалог.
