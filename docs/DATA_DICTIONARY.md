# Словарь данных Supabase

Это логическая модель. Типы SQL, внешние ключи, индексы и политики доступа будут зафиксированы отдельной миграцией.

Все таблицы находятся внутри schema конкретной компании, например **kompaniya_001**.

## Основные таблицы

| Физическое имя | Понятное название | Назначение |
|---|---|---|
| polzovateli | Пользователи | Одна запись на реального человека внутри компании |
| identifikatory_kanalov | Идентификаторы каналов | Связь пользователя с Telegram, сайтом, Avito, VK, MAX |
| dialogi | Диалоги | Текущее состояние и итог отдельного обращения |
| soobshcheniya | Сообщения | Сырые входящие и исходящие сообщения |
| sobytiya_etapov | История этапов | Когда и почему менялся этап |
| celevye_sobytiya | Целевые события | Телефон, запись на замер, явное желание заказать |
| napominaniya | Напоминания | Задания на сообщение через 20 минут и 24 часа |
| analiz_dialogov | Анализ диалогов | Реакция, ошибки, причины отказа и краткий итог |
| obratnaya_svyaz | Обратная связь | Оценка и текст клиента |
| sobytiya_integraciy | События каналов | Защита от повторной обработки одного события |
| sistemnye_sobytiya | Системные события | Ошибки, предупреждения и техническое состояние |
| dokumenty_znaniy | Документы знаний | Логические документы и их версии |
| fragmenty_znaniy | Фрагменты знаний | Текстовые части документов и embeddings |
| nastroyki_dashborda | Настройки дашборда | Бренд, логотип и параметры интерфейса |

## Ключевые поля документов

### dokumenty_znaniy

| Поле | Значение |
|---|---|
| id | Внутренний идентификатор версии |
| identifikator_dokumenta | Постоянный идентификатор логического документа |
| nazvanie | Название для человека |
| tip_dokumenta | Категория документа |
| imya_fayla | Имя загруженного файла |
| versiya | Номер версии внутри системы |
| versiya_istochnika | Версия, указанная автором документа |
| hash_istochnika | SHA-256 исходного файла |
| hash_normalizovannogo_teksta | SHA-256 очищенного текста |
| status | Состояние обработки |
| aktiven | Используется ли версия в поиске |
| predydushchaya_versiya_id | Ссылка на предыдущую версию |
| model_embeddinga | Модель, которой построены embeddings |
| razmernost_embeddinga | Размерность вектора |
| zagruzil_telegram_user_id | Кто загрузил документ |
| data_zagruzki | Когда файл получен |
| data_publikacii | Когда версия стала активной |
| tekst_oshibki | Причина неуспешной обработки |

Допустимые статусы первой версии:

- **poluchen**
- **proverka**
- **obrabotka**
- **vektorizaciya**
- **proverka_kachestva**
- **aktiven**
- **dublikat**
- **oshibka**
- **arhiv**

Уникальность активного документа определяется парой: **identifikator_dokumenta + aktiven**. Точный дубль определяется по **hash_istochnika** и/или **hash_normalizovannogo_teksta**.

### fragmenty_znaniy

| Поле | Значение |
|---|---|
| id | Идентификатор фрагмента |
| dokument_versiya_id | Версия исходного документа |
| identifikator_dokumenta | Удобная связь с логическим документом |
| nomer_fragmenta | Порядок фрагмента |
| zagolovok_h1 | Главный заголовок |
| put_razdela | Путь вида H1 > H2 > H3 |
| tekst_fragmenta | Текст для поиска |
| kolichestvo_tokenov | Размер фрагмента |
| hash_fragmenta | SHA-256 нормализованного фрагмента |
| metadata | Дополнительные данные JSON |
| embedding | Вектор pgvector |
| model_embeddinga | Модель embedding |
| aktiven | Участвует ли фрагмент в поиске |
| data_sozdaniya | Время создания |

## Важные правила

- Сырые сообщения не перезаписываются аналитикой.
- Время хранится с часовым поясом, отображается в часовом поясе компании.
- Модель embedding и размерность не смешиваются в одном активном поиске.
- Архивные версии не возвращаются клиентскому боту.
- Индекс, SQL-функция поиска, RLS и grants проектируются после утверждения точной SQL-схемы.
