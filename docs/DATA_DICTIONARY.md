# Словарь данных

Описательная модель v0.2 для одной schema компании. SQL, типы, индексы и миграции создаются позже. Перечисленные связи и смысл обязательны для будущей реализации.

## Общие правила

- Все таблицы компании находятся в её schema; повторять доступ к чужим schema через общий ключ нельзя.
- ID — внутренние UUID, внешние ID — строки. Даты событий и записи различаются и сохраняют часовой пояс/UTC.
- Исходный текст неизменяем; правка сообщения — отдельное событие/редакция.
- История этапов, целей, потерь, возвратов и административных действий дополняется.
- Структура одинакова у всех компаний; индивидуальные таблицы при обычном копировании не создаются.
- Секреты, Credentials и произвольные исполняемые prompts в этих таблицах не хранятся.

| sobytiya_etapov | id, dialog_id; старый/новый этап, время, причина, источник (правило/LLM/человек), уверенность и доказательное сообщение |

Уникальность идентичности — канал + аккаунт + внешний пользователь внутри schema. Уникальность внешнего сообщения учитывает аккаунт/диалог. Поле первого обращения не обновляется при возврате.

Этапы и статусы определены в [CONVERSATION_LIFECYCLE.md](specs/CONVERSATION_LIFECYCLE.md). Сырые контакты/сообщения имеют отдельные права колонок или закрытые представления; право читать метрики не даёт автоматически право читать весь исходный текст.

## Выполнение, память и аналитика

| Таблица | Поля и назначение |
|---|---|
| sobytiya_integraciy | id; источник/аккаунт/внешний ID; ключ идемпотентности; хэш содержания; время; состояние приёма. Уникальный ключ не допускает второй обработки того же входа |
| zadaniya_obrabotki | id, dialog_id, sobytie_id; тип, статус, число попыток, следующий запуск, владелец/срок аренды и номер владения; актуальная версия состояния |
| ishodyashchie_deystviya | id, dialog_id или zagruzka_id; вид (сообщение, CRM, уведомление), ключ повтора; адресат из доверенного состояния; полезная нагрузка; статус, попытки, срок, внешний ID, подтверждение/безопасная ошибка |
| napominaniya | id, dialog_id; номер (1/2/проверка потери), t0, исходящее сообщение-основание, поколение ожидания; срок, окно актуальности, статус, причина отмены/пропуска, ссылка на исходящее действие |
| pamyat_dialoga | dialog_id; rezyume, последние обезличенные сообщения, подтверждённые факты, obrabotano_do_id, versiya_pamyati; время обновления и происхождение из прежнего диалога |
| analiz_dialogov | id, dialog_id; резюме, тема, реакция, предполагаемые ошибки/пробелы; ссылки на доказательства, уверенность, версия модели/prompt, подтверждение человеком |
| obratnaya_svyaz | id, dialog_id, polzovatel_id; оценка 1–5, текст, дата, канал, ссылка на прежнюю редакцию |
| sistemnye_sobytiya | id; компания/среда, компонент, операция, ID выполнения, время, уровень, код и безопасное описание; состояние/ключ группировки уведомления |
| zhurnal_administrirovaniya | id; автор, действие, объект, время, безопасные изменения и результат |

Исходящее действие и сообщение — связанные, но разные сущности: одна запись описывает попытки отправки, другая — реплику диалога. Повтор попытки не создаёт новое логическое сообщение. Отдельная строка памяти не заменяет архив.

Система определяет пользователя отчёта по событиям, не по сумме диалогов; правила находятся в [METRICS.md](specs/METRICS.md).

## База знаний

| Таблица | Поля и назначение |
|---|---|
| zagruzki_znaniy | id; ID события Telegram, отправитель/чат, имя файла; ishodnyy_fayl (исходные байты), размер, hash_istochnika; время/порядок приёма; status, код ошибки, документ/версия при наличии |
| dokumenty_znaniy | id; уникальный identifikator_dokumenta; aktivnaya_versiya_id (может быть пустым до публикации или после отзыва); время создания |
| versii_dokumentov_znaniy | id, dokument_id, zagruzka_id; nomer_versii, nazvanie, tip_dokumenta, versiya_istochnika, data_obnovleniya; hash_soderzhaniya, otpechatok_obrabotki, profil_indeksa_id; status; время проверки/публикации/архивирования; ожидаемая предыдущая версия |
| fragmenty_znaniy | id, versiya_id; nomer_fragmenta, put_razdela; tekst_fragmenta (точный текст для embedding с заголовками), kolichestvo_tokenov, hash_fragmenta, vektor; время создания |
| profili_indeksa | id; модель/размерность embedding, версия parser/очистки/чанкинга, размеры и токенизатор; неизменяемый снимок параметров из n8n для воспроизводимости |
| kontrolnye_voprosy | id, versiya_id; vopros, ozhidaemyy_razdel, ozhidaemyy_fakt при наличии; источник эталона |
| proverki_znaniy | id, versiya_id, vopros_id; профиль/порог/лимит поиска, полученные ID фрагментов, результат проверки, время/ошибка |

Один документ — много версий; одна версия — много фрагментов. Только aktivnaya_versiya_id определяет клиентскую видимость. Ссылка обязана вести на опубликованную версию того же документа; это проверяется БД.

Уникальны dokument_id + nomer_versii и versiya_id + nomer_fragmenta. Одинаковый текст в разных разделах допускается. Нет уникальности по паре «документ + false» и нет независимого aktiven у каждого фрагмента.

## Дашборд

| Таблица | Поля и назначение |
|---|---|
| nastroyki_dashborda | Оформление, путь логотипа, часовой пояс отображения, подписи/порядок этапов, видимые разделы, период по умолчанию, версия изменения |
| dostupy_dashborda | ID пользователя Auth, роль rukovoditel/razrabotchik, разрешённый доступ к перепискам, активность, дата выдачи/отзыва |
| versii_ustanovki | Версия эталона, миграций, конфигурации и адаптеров; среда, дата применения, ссылка на безопасное подтверждение приёмки |

Системные auth-таблицы Supabase не переименовываются и не копируются в каждую schema. Членство конкретной компании проверяет сервер дашборда.

## Что уточняет будущая SQL-задача

Типы/обязательность, внешние ключи, индексы, функции атомарных операций, ограничения прав, сроки очистки и представления отчётов. Она реализует эту модель и не может молча удалить поля или поменять бизнес-смысл.

Связи и форматы операций: [INTEGRATION_CONTRACTS.md](specs/INTEGRATION_CONTRACTS.md). Доступ: [ACCESS_AND_ISOLATION.md](specs/ACCESS_AND_ISOLATION.md). Никакие таблицы из этого документа пока не созданы на сервере.
